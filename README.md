## 1. 프로젝트 개요

**전기 상식 퀴즈 게임**은 파이썬의 핵심 문법, 객체지향 프로그래밍(OOP), JSON 파일 기반 데이터 영속성을 실무적 관점에서 종합 적용한 콘솔 기반 퀴즈 프로그램입니다.

사용자는 터미널 환경에서 전기 기초 이론 문제를 풀며 실시간으로 정답률(100점 만점 환산)을 확인하고, 원하는 퀴즈를 직접 추가하거나 삭제할 수 있으며 모든 데이터는 영구 보존됩니다.

---

## 2. 주제 선정 이유

전기 및 회로 기초 이론(옴의 법칙, 전하, 교류 전원 등)은 공학 및 일상 기술 이해의 핵심 바탕입니다.
학습자가 직관적인 CLI 환경에서 문제를 풀고 힌트를 확인하며 자신의 이해도를 점검할 수 있도록 **전기 상식 퀴즈**를 프로젝트 주제로 선정했습니다.

| 기능               | 설명                                                 | 입력 예외 처리 및 검증 기준                   |

## 5. 모듈 호출 흐름 및 관심사 분리

관심사 분리(Separation of Concerns) 원칙을 기반으로 **입력 검증**, **게임 진행**, **데이터 입출력** 로직의 책임을 3단계로 명확히 분리했습니다.

```text
[ 사용자 CLI 입력 ]
        │
        ▼
main.py ──────── 1. 입력 정제 및 범위 검증 ────────► input_helper.py
        │                                            │
        │                                            │ (공백 제거, 문자열 예외 처리,
        │                                            │  유효 정수 범위 확인)
        │                                            │
        ◄──────── 2. 검증 완료된 유효 데이터 반환 ───┘
        │
        ├── 1. play_quiz()
        │       └──► Quiz.is_correct()
        │              └──► 100점 환산 점수 산출
        │
        ├── 2. add_quiz_flow()
        │       └──► Quiz 객체 인스턴스화
        │              └──► QuizGame.quizzes 추가
        │
        ├── 3. show_quizzes_flow()
        │       └──► 등록 목록 출력
        │
        ├── 4. 점수 / 히스토리 확인
        │       └──► best_score & history 조회
        │
        └── 5. delete_quiz_flow()
                └──► QuizGame.delete_quiz()

        ▼
QuizGame.save_data()

        │
        ▼
[ Atomic Write ]

state.json.tmp 저장
        │
        ▼
os.replace()
        │
        ▼
state.json
```

### 로직 분리 기준

1. **입력 처리/검증 계층 (`input_helper.py`)**
   사용자 콘솔 입력의 타입 변환 오류(`ValueError`), 범위 초과, 공백 입력을 사전 차단하여 순수한 유효 값만 상위로 전달합니다.

2. **영속성 관리 계층 (`game.py` - `save_data`/`load_data`)**
   비즈니스 로직과 파일 시스템을 분리하여 데이터의 직렬화/역직렬화 및 원자적 파일 저장을 전담합니다.
   -->원본 state.json에 바로 쓰지 않고 임시 파일(.tmp)에 먼저 완벽히 기록한 후 os.replace()로 원자적으로 교체
        이를 통해 저장 도중 정전이나 강제 종료(Ctrl+C)가 발생하더라도 기존 데이터가 깨지는 현상을 완벽히 방어

## 6. 클래스 구조 및 OOP 설계 원리

단순 함수나 딕셔너리(`dict`)로만 개발할 경우 상태 데이터와 처리 함수가 분리되어 전역 변수를 남발하게 되고, 데이터 규격이 바뀔 때마다 모든 함수를 수정해야 합니다.

본 프로젝트는 **캡슐화(Encapsulation)**와 **단일 책임 원칙(SRP)**을 적용하여 2개의 핵심 클래스로 책임을 분리했습니다.

### 클래스 명세 및 책임 분리

```text
┌────────────────────────────────────────┐
│                  Quiz                  │
├────────────────────────────────────────┤
│ - question: str                        │
│ - choices: list[str]                   │
│ - answer: int                          │
│ - hint: str                            │
├────────────────────────────────────────┤
│ + display(idx): void                   │
│ + is_correct(user_ans): bool           │
│ + to_dict(): dict                      │
│ + from_dict(data): Quiz (classmethod)  │
└────────────────────────────────────────┘
                    ▲
                    │ 1
                    │
                    │ * (다수 관리)
                    │
┌────────────────────────────────────────┐
│               QuizGame                 │
├────────────────────────────────────────┤
│ - filename: str                        │
│ - quizzes: list[Quiz]                  │
│ - best_score: int                      │
│ - history: list[dict]                  │
├────────────────────────────────────────┤
│ + load_data(): void                    │
│ + save_data(): void                    │
│ + delete_quiz(index): Quiz             │
│ + play_quiz(input_fn): void            │
│ + show_history(): void                 │
│ - _init_default_data(): void           │
└────────────────────────────────────────┘
```

* **`Quiz` 클래스**: 문제, 보기, 정답, 힌트 데이터를 캡슐화하고, 스스로 정답 여부를 판정(`is_correct`)하며 JSON 데이터로 상호 변환(`to_dict`/`from_dict`)하는 책임을 가집니다.
* **`QuizGame` 클래스**: `Quiz` 인스턴스들의 라이프사이클을 관리하며, 게임 진행, 최고 점수 갱신, 파일 로드 및 원자적 저장을 총괄합니다.

### 요구사항 변경 시 수정 가이드

코드가 역할별로 분리되어 있어 향후 변경 요구사항에 유연하게 대응할 수 있습니다.

* **채점 및 점수 계산 로직 변경 시**: `game.py`의 `QuizGame.play_quiz()` 메서드만 수정합니다.
* **선택지 개수 변경(4개 ➔ N개) 및 문제 속성 확장 시**: `quiz.py`의 `Quiz` 클래스 필드와 `main.py`의 `add_quiz_flow()` 입력 루프만 수정합니다.
* **입력 유효성 범위 및 예외 규칙 변경 시**: `input_helper.py`의 `get_valid_int()`만 수정합니다.

## 7. 데이터 파일 명세 (state.json)

프로그램은 프로젝트 루트의 `state.json` 파일을 데이터 저장소로 사용합니다.

### JSON 포맷 선정 이유

1. **가독성 및 직관성**: 텍스트 기반 포맷으로 문제, 선택지, 정답 데이터를 육안으로 쉽게 확인하고 편집할 수 있습니다.
2. **Python 표준 호환성**: 파이썬의 `dict` 및 `list` 구조와 1:1로 매핑되어 내장 `json` 모듈만으로 간결하게 직렬화/역직렬화할 수 있습니다.
3. **경량성 및 독립성**: 별도의 데이터베이스 엔진 설치 없이 단일 파일로 동작하여 어디서나 즉시 실행이 가능합니다.

### 데이터 스키마 및 예시 구조

최상위는 딕셔너리로 `quizzes`(문제 목록), `best_score`(최고 점수), `history`(플레이 기록)의 관심사를 분리하고, 개별 퀴즈는 `Quiz` 클래스 속성과 1:1 매핑되는 중첩 객체 배열로 설계했습니다.

```json
{
  "quizzes": [
    {
      "question": "전압, 전류, 저항 사이의 관계를 나타내는 법칙은?",
      "choices": [
        "옴의 법칙",
        "패러데이 법칙",
        "키르히호프 법칙",
        "쿨롱의 법칙"
      ],
      "answer": 1,
      "hint": "기호 V = I * R 로 나타냅니다."
    }
  ],
  "best_score": 100,
  "history": [
    {
      "date": "2026-08-14 15:00:00",
      "total_questions": 5,
      "correct_count": 5,
      "score": 100
    }
  ]
}
```

| **필드명**              | **데이터 타입**     | **필수 여부** | **설명**                        |
| -------------------- | -------------- | --------- | ----------------------------- |
| `quizzes`            | Array (Object) | 필수        | 등록된 퀴즈 객체 목록                  |
| `quizzes[].question` | String         | 필수        | 퀴즈 문제 내용                      |
| `quizzes[].choices`  | Array (String) | 필수        | 4개의 보기 선택지                    |
| `quizzes[].answer`   | Integer        | 필수        | 정답 번호 (1~4)                   |
| `quizzes[].hint`     | String         | 선택        | 문제 힌트 텍스트                     |
| `best_score`         | Integer        | 필수        | 역대 최고 점수 기록 (100점 만점 기준)      |
| `history`            | Array (Object) | 필수        | 플레이 이력 (일시, 푼 문제 수, 정답 수, 점수) |

## 8. 파일 저장 정책 및 복구 메커니즘

파일 입출력은 외부 OS 환경과 상호작용하므로 예기치 않은 오류가 발생할 수 있습니다. 이를 방지하기 위해 **Atomic Write** 기법과 다중 **try-except 복구 정책**을 수립했습니다.

### 1. Atomic Write (원자적 저장 기법)

원본 파일에 직접 덮어쓰는 도중 정전이나 강제 종료가 발생하면 파일 전체가 손상될 위험이 있습니다.

따라서 임시 파일(`state.json.tmp`)에 데이터를 완전히 기록한 후, OS 레벨의 원자적 연산인 `os.replace()`를 통해 교체합니다.

```text
[메모리 데이터]
      │
      ▼
state.json.tmp
      │
      │ 완전한 임시 파일 기록
      ▼
os.replace()
      │
      ▼
state.json
      │
      ▼
원자적 교체 완료
```

### 2. 읽기/쓰기 발생 시점 및 순서

* **읽기 (Load)**: 프로그램 시작 시 `QuizGame.__init__()`에서 `load_data()`가 가장 먼저 실행되어 `state.json`을 역직렬화하여 메모리에 적재합니다.
* **쓰기 (Save)**: 퀴즈 추가, 퀴즈 삭제, 게임 종료 후 점수 갱신 시 `save_data()`가 호출되어 즉시 파일 시스템에 동기화됩니다.

### 3. 손상 복구 및 Fallback 정책

* **파일이 없는 경우 (최초 실행)**: `_init_default_data()`가 동작하여 기본 전기 상식 퀴즈 5개(옴의 법칙, 전하 단위, 전류 기호, 직렬 저항, 교류 전원 특징)를 자동 생성합니다.
* **파일 손상 발생 시 (`JSONDecodeError`)**: 기존 손상 파일을 `state.json.bak`로 자동 백업하여 수동 복구 기회를 보존하고, 기본 퀴즈 5개 데이터로 안전하게 초기화하여 프로그램 실행을 유지합니다.

## 9. 대량 데이터 확장성 분석 및 개선 방안

현재 방식은 단일 JSON 파일을 통째로 메모리에 로드하는 구조입니다.

퀴즈 데이터가 1,000개 이상으로 대량 증가할 경우 발생할 수 있는 한계와 개선 방안은 다음과 같습니다.

| **발생 가능한 한계점** | **구체적 현상 및 영향**                                    | **해결 방안**                                                      |
| -------------- | -------------------------------------------------- | -------------------------------------------------------------- |
| **I/O 병목**     | 퀴즈 1개 추가/삭제 시에도 수천 개의 전체 데이터를 다시 인코딩하여 파일 전체를 다시 씀 | **JSON Lines (`.jsonl`) 포맷 적용**: 줄바꿈 단위로 `O(1)` Append-Only 추가 |
| **검색 속도 저하**   | 특정 문제 검색이나 중복 검사 시 리스트 전체를 순회하므로 `O(N)` 시간 소요      | **SQLite 경량 DB 전환**: B-Tree 인덱스를 통해 검색 속도를 `O(log N)`으로 최적화    |
| **메모리 오버헤드**   | 프로그램 구동 시 모든 퀴즈 데이터를 한 번에 메모리에 상주시켜야 함             | **페이징/스트리밍 조회**: 필요한 퀴즈 개수만큼만 커서 단위로 메모리에 적재                   |

## 10. Git 워크플로우 및 브랜치 병합 증빙

프로젝트의 안정적인 관리를 위해 표준 커밋 컨벤션을 준수하고 기능 단위 브랜치를 분기하여 병합(`Merge`)하는 워크플로우를 적용했습니다.

### Commit Convention

```text
타입: 작업 내용 요약
```

* `Feat`: 신규 기능 개발 (퀴즈 풀기, 추가, 삭제, 힌트, 히스토리 등)
* `Fix`: 버그 수정 (입력 유효성 검증, 인덱스 에러 방지 등)
* `Docs`: README 명세 및 실행 증빙 갱신
* `Refactor`: 코드 구조 개선 및 책임 분리

### 브랜치 병합 및 분기선 증빙

메인 브랜치의 안정성을 보호하기 위해 기능별 브랜치(`feature/score-policy` 등)를 생성하여 독립적으로 개발을 완료한 후 `--no-ff` 옵션을 통해 병합 커밋 이력을 명확히 남겼습니다.

```text
*   Merge: feature/score-policy 브랜치를 main으로 병합
|\
| * Feat: 100점 만점 기준 점수 정책 문서 추가
|/
* Docs: 평가 기준 항목 전체 반영 및 README 최종 업데이트
```

### Git Clone & Pull 실습 터미널 증빙

별도의 로컬 환경에서 원격 저장소를 복제(`clone`)하고, 변경 사항을 동기화(`pull`)하는 실습을 정상적으로 수행했습니다.

```bash
# 1. 별도 디렉터리에서 저장소 복제 실습
$ git clone https://github.com/juhoo03/python-quiz-game.git test-repo
Cloning into 'test-repo'...
remote: Enumerating objects: 76, done.
Resolving deltas: 100% (38/38), done.

# 2. 원격 저장소 최신 변경사항 동기화 실습
$ git pull origin main
From https://github.com/juhoo03/python-quiz-game
 * branch            main     -> FETCH_HEAD
Already up to date.
```

## 11. 새로운 환경에서 설치 및 실행 방법
